# Как выпускаются обновления RollHelper

## Что считается обновлением

Исходники в репозитории — единственный источник правды. Файлы внутри `%LOCALAPPDATA%\Programs\RollHelper` являются установленными копиями. Их можно временно менять для проверки, но такое изменение не считается готовым обновлением и будет потеряно при следующей установке.

У каждого компонента своя версия:

- `launcherVersion` — интерфейс лаунчера;
- `rollhouseVersion` — основной пакет RollHouse;
- `reportLoadVersion` — дополнение «Отчёт — нагрузка»;
- `catalogVersion` — версия списка, который скачивает лаунчер.

Если изменился только отчёт, повышаются `reportLoadVersion` и `catalogVersion`. Если изменился основной `main.ahk`, сервер или общая логика RollHouse, повышаются `rollhouseVersion` и `catalogVersion`. Версия лаунчера меняется только при изменениях самого лаунчера.

## Порядок выпуска

1. Изменить исходный файл в репозитории.
2. Проверить работу и синтаксис.
3. Обновить нужные версии в `packaging/package-release.json`.
4. Зафиксировать изменения в Git и отправить их в `master`.
5. Выполнить:

   ```powershell
   .\packaging\publish-package-release.ps1 -Publish
   ```

6. В лаунчере нажать «Обновить список программ».
7. Для изменённого компонента появится состояние «Доступно обновление» и отдельная кнопка обновления.

После установки запущенный RollHouse или открытое окно дополнения нужно перезапустить: Windows не заменяет код уже работающего процесса в памяти. Это перезапуск новой установленной версии, а не скрытое редактирование файлов.

## Что увидит оператор

- Изменился лаунчер: появляется кнопка «Обновить лаунчер до …».
- Изменился RollHouse: строка RollHouse показывает доступное обновление.
- Изменилось дополнение: обновление появляется только у этого дополнения под RollHouse.
- Простое закрытие и повторное открытие окна без установки обновления ничего нового показывать не должно.
