# RollClub: свёрнутое окно Syrve

Сценарий: Ctrl+F4 проверяет и бронирует один подходящий заказ при свёрнутом
Syrve Office, без системной мыши, клавиш и активации окна.

Разрешённые пакеты: `rollclub`, каталог. Маркер `rollclub-duty`, лаунчер,
RollHouse, другие дополнения и пользовательские данные не меняются.

Защищены тильда, Enter, F1, Ctrl+Enter, Ctrl+F2, правила отбора заказов,
остановка после одного заказа и прежний координатный путь развёрнутого окна.
Новый путь используется только при свёрнутом Syrve и не откатывается к кликам.

Проверки: тесты чтения таблицы и кеша, AHK-синтаксис основного файла и нового
include, профильные `test_rollclub_*.py`, AHK-тесты чистых UIA-помощников,
ZIP/SHA-256/manifest перед публикацией. Журнал: `rollclub_duty_background.log`.

Ручная проверка оператором ещё не выполнена: холодный запуск со свёрнутым Syrve;
появление нового заказа; бронь ровно нужного номера; гонка с другим оператором;
повторный Ctrl+F4; ручная работа после остановки; потеря UIA; другая программа
на переднем плане; 100/125/150% и разные разрешения. Отсутствие UIA-pattern
должно останавливать режим с понятной причиной, не разворачивая Syrve.

Ссылки `docs/VERIFICATION_STANDARD.md`, `docs/VERIFICATION_REGISTRY.md` из
контрактов отсутствуют в исходном master; их содержимое не предполагалось.

## Результаты автоматической проверки

- 29 Python-тестов дежурства проходят, включая 8 новых проверок фонового чтения.
- 16 исполняемых AHK-проверок: точный номер строки, разрешённые действия,
  запрет selection-only/disabled, ограничение обхода, отмена старого запроса.
- Основной AHK-файл проходит `/ErrorStdOut /iLib NUL`; UTF-8 BOM сохранён.
- Полный набор: 91 тест, те же 2 failures и 2 import errors, что в исходном
  master (83 теста). Существующие проблемы: отсутствующие parser,
  refund.ahk и сборщик Гункана, устаревшее ожидание в тесте времени/зон.
- У опубликованного `v0.1.110` основной AHK и reader совпадают с `865d21b`.
  Сборка использует его ZIP только как закреплённую SHA-256 зависимость сервера
  и runtime, отсутствующих целиком в Git. Правки берутся из текущих исходников;
  установленная программа и локальный сервер не используются.
- Сборщик сравнивает каждый защищённый файл ZIP и все остальные пакеты каталога
  побайтно/по полям, проверяет CRC и компилирует Python-маршрут.
- Упакованный HTTP-маршрут отдельно проверен: обычное чтение, фоновый HWND,
  некорректный HWND. Рабочий сервер и Syrve при тесте не запускались.
