# RollHelper: обязательные правила для агентов

Перед любым изменением кода, пакетов, лаунчера или релиза прочитайте в указанном порядке:

1. `docs/CODEMAP.md`
2. `docs/STABLE_BEHAVIOR_CONTRACTS.md`
3. `docs/RELEASE_GUARDRAILS.md`
4. README изменяемого бренда или дополнения
5. `STATUS.md`

## Нельзя

- Менять соседний бренд или дополнение «заодно».
- Считать установленную папку, архив или старую portable-копию источником правды.
- Удалять координатный fallback до ручной проверки новой UIA/WinAPI-привязки в Syrve.
- Сообщать оператору об успехе без проверки результата или однозначного журнала.
- Перезаписывать `UserData`, KML, PLU, горячие клавиши, WinAPI-привязки и состояние лаунчера при обновлении.
- Выпускать маркерное дополнение вместо базового бренда, если обработчик фактически находится в основном AHK-файле бренда.
- Публиковать релиз без синтаксической проверки AHK, профильных тестов и проверки ZIP/SHA-256/manifest.

## Перед правкой

Зафиксируйте в рабочем плане:

- пользовательский сценарий, который меняется;
- package ID, которые разрешено менять;
- защищённые сценарии, которые должны остаться прежними;
- тесты, журналы и ручную проверку, подтверждающие результат.

Если реальный код противоречит документации, не переписывайте документацию молча. Сначала установите, что является регрессией, а что было согласованным изменением поведения.
